# Plan: Human Atlas Game Mode

## Context

The Human Atlas has 2,234 parts across 15 systems, with 3,432 named concepts. The `atlas.json` manifest provides `parts` (with `name`, `system`, `conceptId`) and `concepts` (with `name`, `elements[]`). The existing `onSelect` callback in `page.tsx` returns a part ID when the user taps/clicks a structure, and `EXPLANATIONS` provides descriptions for ~9 major organs plus system-level descriptions.

**Key integration point:** When the user selects a part on the 3D model, `choosePart(id)` fires with the part's ID. In game mode, we intercept this to check if the selected part matches the target answer.

## Design Decisions

### Leaderboard: Combined with difficulty multiplier

One unified leaderboard, but scores are weighted by difficulty. This rewards harder levels without fragmenting the boards:

| Difficulty | Multiplier | Typical structures |
|---|---|---|
| Elementary | 1x | Heart, brain, stomach, lungs, bones (femur, skull) |
| Middle School | 1.5x | Liver, spleen, kidneys, trachea, major arteries |
| High School | 2x | Pancreas, adrenal glands, specific vertebrae, valves |
| College | 3x | Cranial nerves, specific muscles, lymph nodes, ducts |
| Medical School | 5x | Small named structures, fascicles, specific ligaments |

Each correct answer earns base points (time bonus + accuracy) multiplied by the difficulty. This makes a single leaderboard meaningful — a perfect Medical School run will outscore a perfect Elementary run.

### Leaderboard storage: Snowflake table via API route

Since this is a static site on SPCS with no backend, we'll use **localStorage** for the leaderboard. This keeps it simple and avoids needing a backend API. Scores persist per-browser and we show Top 10 Today and Top 10 All Time from the local store. A Snowflake-backed leaderboard would require adding a backend service, which we can do as a follow-up if needed.

### Question types

1. **Find on model** — "Tap the [structure name]" — user must click the correct part on the 3D body. No search allowed. Worth more points for speed.
2. **Multiple choice** — "Which system does the [structure] belong to?" or "What is the function of [structure]?" — 4 options, one correct.
3. **System identification** — "Tap any structure in the [system name] system" — user must find and click any part belonging to that system.

Each 5-question quiz mixes these types (e.g., 2 find-on-model, 2 multiple choice, 1 system identification).

## Implementation

### Step 1: Question bank (`game-questions.ts`)

Defines question pools per difficulty level. Each difficulty maps to a curated list of concept names (elementary = major organs, medical school = obscure structures). At runtime, questions are generated by:

1. Filtering atlas concepts to the difficulty's allowed set
2. Randomly picking 5 concepts
3. Assigning question types (find-on-model, multiple-choice, system-id)
4. Generating wrong answers from other concepts in the same/different systems

```ts
export type Difficulty = 'elementary'|'middle'|'high'|'college'|'medical';
export type QuestionType = 'find'|'multiple-choice'|'system-id';
export interface Question {
  type: QuestionType;
  prompt: string;
  targetConceptName: string;    // correct answer concept name
  targetPartIds: string[];      // valid part IDs for "find" questions
  targetSystem?: SystemId;      // for system-id questions
  choices?: string[];           // for multiple-choice (4 options)
  correctChoice?: number;       // index into choices
  difficulty: Difficulty;
}
export function generateQuiz(atlas: Atlas, difficulty: Difficulty): Question[];
```

Difficulty pools (examples):
- **Elementary:** heart, brain, stomach, lung, femur, skull, ribs, spine, eye, ear
- **Middle School:** liver, spleen, kidneys, trachea, aorta, esophagus, bladder, diaphragm
- **High School:** pancreas, adrenal gland, thyroid, specific vertebrae, pelvis, humerus
- **College:** specific muscles (deltoid, biceps), specific nerves, coronary arteries, bronchi
- **Medical School:** deep structures — smaller named vessels, ligaments, fasciae, specific organ subparts

### Step 3: Game UI component (`game.tsx`)

A self-contained component that overlays the existing explorer. States:

```
START → difficulty select → PLAYING (question 1..5) → RESULTS → LEADERBOARD
```

**Start screen:** "Game Mode" title, difficulty selector (5 buttons), Start button.

**Playing:** 
- Top bar shows question number (1/5), score, timer countdown (30s per question)
- Center prompt shows the question text in a floating panel
- Search panel and systems panel are hidden during game mode
- For "find" questions: user taps the 3D model; correct = green flash + points, wrong = red flash + try again (up to 3 attempts)
- For "multiple choice": 4 buttons appear in the prompt panel
- Points: base 100 per correct answer, bonus for speed (up to 100 extra), penalty for wrong attempts (-25 each). Multiplied by difficulty.

**Results:** Score summary, correct/total, "Enter your name" field, Submit to leaderboard button.

**Leaderboard:** Two tabs — "Today" and "All Time" — each showing Top 10 with rank, name, score, difficulty badge, date.

### Step 4: Integrate into `page.tsx`

- Add a game mode state: `const [gameMode, setGameMode] = useState(false)`
- Add a "Game" button in the top actions nav (using Lucide `Gamepad2` icon)
- When `gameMode` is true:
  - Hide search panel, systems panel, and detail sheet
  - Pass a `gameOnSelect` callback instead of `choosePart` to `AnatomyScene`
  - The `gameOnSelect` checks if the tapped part matches the current question's target
- Reset scene to default view when entering game mode

### Step 5: CSS styling

- `.game-overlay` — floating glass panel centered on screen for start/results/leaderboard
- `.game-hud` — top bar during gameplay (question counter, score, timer)
- `.game-prompt` — question text panel (bottom-center, above the dock area)
- `.game-choices` — multiple choice button grid
- `.game-feedback` — correct/wrong flash animation
- Dark mode variants for all game surfaces

Standard Docker build + push + service recreation.

## Scoring Formula

```
base_points = 100
time_bonus = max(0, floor((time_remaining / 30) * 100))
attempt_penalty = (attempts - 1) * 25
question_score = max(0, (base_points + time_bonus - attempt_penalty))
final_score = sum(question_scores) * difficulty_multiplier
```
